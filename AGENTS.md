# Agent instructions

## Documentation and comments

Write plain, direct prose that is accessible to someone new to the library.

- Keep technical details that help the reader and remove details that only add noise. Check the implementation before describing behavior.
- Use complete sentences. Avoid slogans, fragments, and artificial contrasts such as “no A, no B” or “A, not B.”
- Avoid decorative metaphors and unusual verbs when simple, precise wording is available. For example, prefer direct descriptions over phrases such as “rides over the wire” or “carries its value.”
- Public documentation should explain results, important constraints, and behavior that affects correctness. Internal comments should explain why code exists or clarify non-obvious behavior instead of restating the code.
